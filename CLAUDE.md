# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project

"Kanka's Gang" — 2D pixel-art side-scroller platformer. Vanilla JavaScript (ES modules) + Canvas 2D. **No dependencies, no build step, no test suite, no linter.** Code, comments, asset names and UI text are in Portuguese (pt-BR); keep new code consistent with that.

## Commands

```bash
# Build the game: index.html is GENERATED (self-contained, double-click to play, no server). Never edit it by hand;
# the HTML/CSS shell lives in MODELO inside tools/empacotar.py.
# Moves the previous build to backup/index_<date>.html (skipped if output is unchanged).
python3 tools/empacotar.py

# URL params: ?debug (draws hitboxes/collision boxes) · ?fase=2 (start at phase 2)
# window.jogo exposes the Game instance in the browser console.

# Asset generator (Python 3.9+, Pillow, numpy)
python3 tools/gerar_assets.py                 # create only MISSING assets
python3 tools/gerar_assets.py --tabela        # regenerate ASSETS.md from the manifest
python3 tools/gerar_assets.py --forcar <path> # regenerate specific files, e.g. audio/musica/titulo.wav
```

Never run `--forcar` without paths: it overwrites all art/audio, including user-replaced files.

**The user plays only the offline build.** After any change to code or assets, run `python3 tools/empacotar.py` so `index.html` is current; never delete or overwrite files in `backup/` (one file per previous version).

The playable heroes (Samurai Jeff, Kanka, Paulinho) wear the gang uniform: black with orange details (`UNIFORME_GANGUE` in `tools/arte/personagens.py`, `RETRATOS` in `tools/arte/menu.py`). Enemies keep their own colors. Characters are drawn compact/chunky in a Metal Slug style (big head, short thick legs, shading + cloth texture) by `boneco()` in `tools/arte/personagens.py`.

Naming the user asked for: the power-up excavator is the **"máquina customizada"** (never "Mega-Zorde"). The excavator art follows the user's reference photo (yellow boom/stick, black body and cab, yellow engine hood, black tracks); its boom-tip tool is either the yellow **Gripen** grapple or a red/black **harvester head (cabeçote)**. The gang pickup truck is white with a black band and red stripe — no real brand logos.

## Architecture

- **`assets/manifest.json` is the single source of truth for assets.** Every image/sound/data file, its frame size, frame count, fps and loop flag is declared there. `core/Assets.js` loads everything from it; `tools/gerar_assets.py` uses it to create placeholders and write `ASSETS.md`. Asset ids are paths without extension (`personagens/kanka/correndo`). Entries with `"boot": true` load first (font + loading bar) before `BootScene` loads the rest. Adding an asset = add a manifest entry (then `--tabela` to refresh ASSETS.md). Never edit ASSETS.md by hand.
- **Offline bundle** (`tools/empacotar.py`): embeds every `src/` module as a data: URL behind an import map (relative imports rewritten to `src/...` bare specifiers) and every `assets/` file as a data: URL in `window.ARQUIVOS`. All asset URLs must go through the `url()` helper in `core/Assets.js` or they break in the bundle. Dynamic `import()` is not supported by the bundler.
- **Code never draws art procedurally** — it only positions, flips and rotates images from `assets/`. All placeholder art/sound is generated by `tools/arte/` and `tools/som/`.
- **Sprites are horizontal strips.** Characters/enemies face right, feet on the bottom row centered at x = 32 of a 64×64 frame. `Animator` plays a strip by file name within an entity's sprite folder; `anim.entered(frame)` is how attack logic triggers on specific frames.
- **Game loop** (`core/Game.js`): fixed 60 Hz simulation with accumulator (max 5 steps/frame), one draw per rAF. Scenes are plain objects with `enter/exit/update(dt)/draw(renderer)`; switch via `game.transitionTo(() => new Scene(...))` (fade, scene created mid-fade). Flow: Boot → Title → Select → Game → Continue / Ending / Goodbye.
- **Input** (`core/Input.js`): game code queries actions (`'jump'`, `'attack'`…), never keys. Remap in `KEY_BINDINGS` / `PAD_BUTTONS`.
- **Mobile** (`ui/TouchControls.js`): on touch devices (`MOBILE_QUERY` in `constants.js`) DOM buttons call `input.setTouch(action, down)`. Game is forced landscape: fullscreen + `screen.orientation.lock` on tap (Android), else CSS rotates `#jogo` 90° in portrait (CSS lives in `MODELO`, `tools/empacotar.py`). When rotated (`isRotated()`), any screen→game coordinate mapping must swap axes (see `Input.attachPointer`, `Renderer.fit`, d-pad).
- **Tuning lives in `src/config/`**: `characters.js` (movement, attacks, per-frame hitboxes), `enemies.js`, `phases.js` (phase order, enemy type per phase, parallax factors), `constants.js` (resolution 384×216, 16 px tiles, arcade rules). Jump physics are specified as `jumpHeight` + `timeToApex`; gravity/impulse are derived.
- **Hitbox convention**: `{x, y, w, h}` relative to the entity's feet (bottom center), facing right; `active` maps animation frame → box. `Entity.worldBox()` mirrors for facing left. Verify with `?debug`.
- **Entities**: `Entity` (AABB body, x/y = top-left, constructed from feet position) → `Player` (shared platformer feel: coyote time, jump buffer, variable jump, hitstop) with per-character subclasses in `entities/characters/` overriding attack hooks (e.g. Kanka's `_tryAttack`/`onAttackFrame` throws `ToolProjectile`). `Enemy` base handles physics/patrol/perception/damage; subclasses (`LogMax`, `Ponssee`) implement only `think()`.
- **`scenes/GameScene.js`** wires everything: level, spawns, player/enemy projectile lists, items, effects, camera, HUD, pause, hitstop, death/respawn at checkpoint, phase clear. States: intro → play ⇄ paused; play → dying | clear. Character/enemy ids map to classes via `PLAYER_CLASSES` / `ENEMY_CLASSES`.
- **Levels** (`world/levels/faseN.js`): arrays of 15-row ASCII sections concatenated horizontally; `world/Level.js` parses them into a collision grid (SOLID / ONE_WAY), autotiles against a 4×4 `tileset.png`, and extracts decorations and spawns. Legend and design constraints (3 free rows under blocks, max 2-tile steps, 2–3 tile gaps for Paulinho) are in README.md. `world/Physics.js` resolves AABB vs tiles X then Y.
- **Máquina customizada** (`entities/Maquina.js`, `config/maquina.js`, art in `tools/arte/maquina.py`): `X` in a level = 64×64 `Crate` whose cells are made SOLID in the collision grid until it breaks; it is a hit target like an enemy (`GameScene._targets()`). Breaking it spawns a `ParkedExcavator` with a random tool (`garra` | `cabecote`); touching it calls `Maquina.board()`, which sets `player.maquina` and swaps the Player's body, `move` (gravity/jump are getters), attacks (`maquina.tool.attacks`) and `anim` — the Player object itself stays the scene's player. `Level.removeTiles()`/`setCell()` edit tiles at runtime (stumps, log piles). The operator's face is the chosen character's HUD portrait drawn into the cab window (`MAQUINA.operator`). Tool tip positions per frame (`tools[*].tips`) come from `cd tools && python -m arte.maquina`.
- **Truck intro/outro** (`entities/Caminhonete.js`): without a checkpoint, `GameScene` hides the player (`player.hidden`), the truck `arrive()`s and `_jumpOut()` drops the player from the bed; at the goal `Player.autoBoard()` runs/jumps into the parked `endTruck`, `_checkBoarding()` hides the player, the camera follows the truck, and the results screen waits `clearDelay`.
- **Phase codes**: `code` per phase in `config/phases.js` (`phaseByCode`), shown on the intro banner, results and continue screens; entered in `scenes/CodeScene.js` (Title → CÓDIGOS), last code saved in localStorage (`scenes/highscore.js`). `SelectScene` takes `{ phaseIndex }`.
- **Feedback / "realism"**: `Effects.js` has `spawnExplosion` (enemy deaths), `spawnDebris`, `spawnSmoke`; enemies flash white on hit (`Renderer.frame({ flash })` via `ctx.filter`); footsteps fire on run-cycle contact frames (`_footsteps()` in Player/Enemy); character voices use `def.voice` as playback rate (`Player.voice()`).
- **New phase**: `levels/faseN.js` + `assets/cenarios/faseN/` (same file set as fase1) + manifest entries + a line in `config/phases.js`.
